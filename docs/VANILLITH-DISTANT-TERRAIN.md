# Vanillith distant terrain

These notes describe the distant-terrain work and its measurements at the time.
For the current playable-world status, see [Vanillith](VANILLITH.md).

Settings → Distant Terrain exposes independent cached full-mesh visibility (2–32 chunks), surface LOD on/off, and LOD distance (4–64 chunks). The regular render distance remains the near-field setting. Distances are maximums: only generated, retained chunks are available, and bounded cache eviction can shorten the visible area. This does not request unseen terrain or increase generation radius.

Hardware presets set near/cached/LOD ranges to Low 2/4/8, Balanced 4/8/16, High 8/16/32. Custom sliders persist independently. Surface LOD is enabled by default. Extra LOD geometry budgets are 16/32/64 MiB respectively, in addition to the existing native, full-mesh and terrain caches; these are not total browser memory limits.

Retired full chunk meshes remain renderable without being reintroduced into gameplay/collision storage or the remeshing queue. Once outside cached full-mesh range, a summary built from the same native heightmap/block arrays can be drawn. It now samples two-block surface cells (previously four), uses the existing atlas and biome tints, and includes short skirts. It has no caves, accurate canopy silhouettes, block entities or collision. This is a visual stand-in for actual generated terrain, not invented unseen terrain or a complete multilevel distant-world renderer. LOD cache is session-local.

LOD construction runs cooperatively after higher-priority publication, lighting and meshing work using leftover frame budget. The pending queue is bounded to 32 native chunks. Geometry and materials are disposed on eviction/exit. Active chunks and visible retained full meshes suppress their LOD counterpart; the immediate 3×3 field never uses LOD. Disabling clears LOD resources; enabling rebuilds available retained chunks. No worldgen RNG, feature order, decoration pipeline or source arrays are changed.

## Verification

Settings → Chunk Streaming separates Active Radius (1–8, default 3: 7×7) from Background Radius (3–48, default 16: 33×33; maximum 97×97). The normal tick path requests nearest chunks first and then background generation even without movement. Background results stay in bounded native/terrain caches and can feed surface LOD; they are not installed as full active/render/collision chunks. Cached results promote through the existing loader when the player approaches. Warm-cache-disabled mode deliberately limits demand to the active radius. Completed background keys prevent an eviction/regeneration loop while stationary; returning after cache eviction can require regeneration. Demand refresh is throttled to twice per second. Terrain-only debug mode remains terrain-only.

Terrain requests/dependency prewarm now use up to four lazy worker instances concurrently, preserving result order and existing request validation. Worker failure rejects only that worker's requests; all workers terminate on exit. Background terrain batches select one available direction per worker. Decoration batches rotate between four cardinal sectors but remain serialized through the existing canonical service, capped at nine outputs. No unordered concurrent decoration passes have been introduced. Four workers consume more CPU/RAM and have startup costs; this is not a demonstrated fourfold speedup.

Performance → Vanillith Memory is now a 256–3072 MiB slider. Hovering and scrolling changes it by 128 MiB; dragging offers finer values. A visible `!` is appended at 2048 MiB and above. Moving it enables custom cache shares: 50% native, 12.5% full mesh, 6.25% terrain, 2% LOD; remaining headroom is nominal. Hardware presets restore legacy preset budgets until the slider is changed. This is NOT a measured/enforceable process RAM cap: browser memory can exceed the target, and large areas/four workers can exhaust memory. The UI explicitly warns about this.

38 targeted tests passed: distant-terrain, hardware-settings, streaming and terrain-preview. They cover slider/wheel behavior, bounded budgets, concurrent dispatch/result order, narrow LOD surface features, immutable arrays, resource disposal, streaming lifecycle, stationary demand, near-only storage and promotion. An isolated Vite production build passed (424 modules); existing bundle/eval warnings remain. These tests do not establish full-world performance or new JAR parity measurements.

The disposable Chromium check in `packages/vanilla-worldgen/scripts/qa-distant-terrain-browser.mjs` uses real WASM terrain-only spectator mode with seed 6888349110149677383. It verifies the retired center is absent from active/native storage but available for cached rendering, then looks back from six chunks away and confirms visible LOD grass pixels. It checks disable and near-field suppression and captures screenshots. It also compares all block, biome, heightmap and fluid-update arrays from four cardinal terrain chunks (±10 chunks on each axis) under four-worker and one-worker dispatch: exact parity, four workers confirmed, no runtime errors. This is a limited terrain-parity/render check, not complete decoration parity or a performance benchmark. The refined center summary used 278 triangles and 19,460 bytes, versus the previous 92 triangles/6,440 bytes.

Run the check against a separate game dev server using `STREAM_URL` (default port 8011) and a Playwright module using `PLAYWRIGHT_MODULE`. Screenshots are written under `/tmp`, without using a saved browser profile.
